## F-05 evidence

The real disposable PostgreSQL suite uses independent interactive transactions, a completed statement marker, and `pg_stat_activity`/`pg_blocking_pids` to prove which session holds the shared gate and which waits. Timeouts bound failed tests; sleeps do not select winners. Both writer-first and importer-first cases cover commit and rollback. A writer-first commit makes import reject the nonempty target; importer-first commit makes the conflicting same-project writer reject WIP admission. Rollback allows the waiting operation. After import, another project fits the remaining lane; same-project and third-project admissions fail. Complete imported history values and original archive bytes match independently; gate revisions, denied writer absence, and all archive/version counts are asserted.

REPEATABLE READ and SERIALIZABLE importers establish their empty-target snapshot before an independent writer commits. Both must abort with SQLSTATE 40001, preserving only that writer's history and gate revision. A rolled-back writer is the positive control: both snapshot isolation levels can import completely. A deliberately incomplete import fails after archive staging and history replay while a direct writer waits at the gate; failure rolls back every import effect and admits the writer. Fixture teardown drops only the schema/roles in the named disposable CI database. Existing canonical CAS, prospective WIP checks and gate SQL are unchanged.

## Read contract

Install `phase1gb2-canonical-catalog.sql` after the existing canonical and synthetic import scripts, only in `ppo_authority_ci`. The fixed `read_catalog_snapshot()` security-definer function has a pinned search path and STABLE volatility. All its internal reads use one calling-statement MVCC snapshot: revision, bounds, current records and every version. Reader/writer roles can execute it; importer and untrusted roles cannot. No direct table permissions or mutation functions are added.

The response carries an exact decimal-string gate revision, status and path-bound current/history record text. Record text preserves PostgreSQL native decimal values before driver JSON parsing can round them. The client validates normalized records and compares original/normalized numeric coefficients and exponents exactly, accepting expanded PostgreSQL notation while rejecting binary64-hidden changes (precision, unsafe integers and underflow). More than 100 runs, 10,000 versions or 32 MiB of JSON-encoded database record text plus per-entry overhead returns `catalog_truncated` with no entries before payload aggregation. These are result bounds, not query-cost or process-memory ceilings: PostgreSQL can still scan/order the authority to derive current rows. The trusted injected transport must bound responses, execute the exact fixed statement in read-committed autocommit, and never retry or fall back to files. There is no production driver or connection configuration.

`createPostgresCanonicalCatalog` requires explicit isolated mode. It bounds and validates the response envelope and every original record before normalization, then uses the complete synthetic migration preflight for every path, identity, full contiguous history, immutable prefix, final-record parity, project/repo/Git-ref binding and WIP check. No unknown fields are silently discarded. A malformed run invalidates the entire catalog and inspection, even if another requested run is valid. More than 20 otherwise valid summaries remains fail-closed `catalog_truncated`, preserving the legacy readiness bound. Empty authority is a valid empty observation. Inspection returns the validated record, all versions and matching legacy summary for one ID only after whole-catalog validation.

Diagnostics distinguish `catalog_invalid`, `catalog_truncated`, `store_unavailable`, `stale_observation`, `invalid_run_id` and `run_not_found`, without disclosing raw error text or partial summaries. Optional `expectedRevision` pins the exact observed revision and denies mismatch; revisions never pass through JavaScript numbers. Revision equality is not a lease, freshness guarantee, execution permit or proof the observation is still current after the statement. Failed CAS/import attempts may also advance the revision. A READ COMMITTED statement blocked at a test advisory barrier before calling the catalog function intentionally returns its older statement revision and histories after another writer commits; the integration test proves STABLE snapshot semantics and denies the observation against the newer pinned revision. The future action transaction must revalidate authority within its own fence.

Summary fields, ordering and terminal/recovery meaning match the legacy filesystem catalog. Its API, routing, policy ID/hash and admission consumers remain untouched. The isolated result has a separate envelope and does not certify admission through the legacy policy contract.

# RIC-157 B2c2 — isolated resource-side fence

Base PR #160 squash `e1b2d7c5ca5540cf6078c3d7faadaccc3e0cb43e`. Optional disposable PostgreSQL laboratory only. RIC-157 stays In Progress, RIC-59/RIC-61 held. No merge without owner approval.

The resource is a single database-owned UUID, fixed synthetic project/path, bounded version and UTF-8 text value. Its actual ref is PostgreSQL SHA-256 of the stored value, not a supplied Git ref. Immutable versions preserve every committed state. There is no real filesystem, Git, Mac/VPS, cross-database or network resource enforcement claim. Only `workspace.write` to `src/synthetic.mjs` is modeled. Reads, tests.local and all unsupported actions are denied by this boundary, never converted to commands.

A separate Ed25519 coordinator signature over `["ppo-synthetic-resource-operation-v1", descriptorText]` authenticates the exact bounded descriptor bytes. The descriptor binds source/target authority identities and generation, host/key/epoch/worker/capability, request/claim/proof hashes, ticket and ticket hash, native registered context hash, canonical run/version/status/branch/base/head, resource UUID/version/current ref, exact action/path, operation UUID and SHA-256 of the exact payload. The signing helper is synthetic infrastructure, not enrollment. Trusted verifier role validates the signature against an independently pinned coordinator public key; SQL independently compares its fingerprint against the authenticated action context. This remains the same trusted server-role/transport/key-custody boundary as B2c1, not SQL Ed25519 verification or a client JSON interface.

`register_resource_operation` attests immutable descriptor/payload bytes under the existing canonical gate. `apply_resource_operation` obtains that same gate and revalidates all B2c1 mutable host/claim/request/canonical/catalog/WIP/ownership authority, plus actual current resource identity/version/ref/path/project. It then invokes fresh action consumption inside this transaction, appends the resource version and immutable receipt, and checks freshness again. A previously consumed diagnostic ticket cannot be reused. A false/exception rolls back every effect; nonce, resource and receipt commit atomically. The unique operation and resource-version indexes and durable action tombstone prevent duplicate effects. No retry, fallback, delete, history repair or reset endpoint exists.

The client owns one dedicated transaction connection per attempt. It reuses B2c1 pre-COMMIT/deferred/post-ack database clock checks and evidence binding, then fetches the exact operation/hash receipt. Receipt inspection is read-only: absence is unknown, never proof of noncommit or retry permission. Positive receipt evidence reports only a committed synthetic effect, even if later authority or ref state has changed. Callers must durably retain the exact operation/ticket/descriptor digest before dispatch; this module supplies no production outbox. Unknown or delayed responses cannot unlock another attempt in that adapter. Replay from a new process is still denied by durable uniqueness.

Every outcome retains `grant:false`, `canExecute:false`, `releaseAuthorized:false`. No successful Phase1F callback is wired. PostgreSQL wall-clock checks are samples, not an atomic wall-clock commit/ack guarantee: expiry can occur after the last deferred check during WAL/COMMIT/transport. A committed synthetic effect/receipt/tombstone may therefore remain while the adapter denies acknowledgment freshness. This preserves the strict 1G-A executable freshness blocker. B2c1's actual-COMMIT delay tests remain in the complete suite; resource tests also cover waits, time spent inside the mutation, precommit and acknowledgment delay. No claim of live authorization follows a synthetic effect.

Roles are narrowly scoped: resource verifier can read context and register authenticated operations; resource consumer can apply a fixed operation and inspect exact receipts/freshness; synthetic initialization belongs only to the existing lab admin. Ordinary roles cannot mutate versions, operations or receipts directly or execute private binding helpers. Search paths are pinned and existing owner default privileges exclude PUBLIC execution. Privileged administrators/schema changes/backup restore remain outside this guarantee.

Bounds: one resource, versions 0..999, payload 4096 UTF-8 bytes, descriptor 8192 bytes, at most 1000 immutable registered operations. Existing B2c1 context/nonce/catalog bounds remain. Exhaustion denies without pruning. These are accepted-input/storage/result bounds, not measured query-cost or process-memory ceilings. M-03 measured timeout/lock/idle/concurrency/connection/memory/disk/transport budgets and load/cancellation evidence remain mandatory. Authenticated transport/key custody, protected actual source/resource fences and live Git CAS, anti-rollback restore policy and separate owner pilot approval remain prerequisites.

Tests use actual disposable PostgreSQL with independent connections and server-observed blocking. Positive rollback controls prove current operations are valid before authority/ref corruption probes. Denied or rolled-back operations preserve exact resource history/receipt/nonce snapshots. Committed operations require atomic version/receipt/tombstone parity. Existing canonical/native JSONB/raw archive guarantees are unchanged and their complete integration suite is retained. No production credentials, actual host enrollment, remote dispatch, generic runner, routing, migration, deployment, retirement or factory cycle is added.
